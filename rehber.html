CachyOS Setup Manager — Genel rehber

Bağımsız topluluk aracı; CachyOS projesinin resmi ürünü değildir. Kurulumdan önce yedek alın.

1. Başlatma

bash launch.sh

Normal kullanıcıyla çalıştırın. Önce kurulum planını inceleyin. AUR kaynaklarını ayrıca değerlendirin.

2. Uygulamalar

Arayüzde kategori ve durum filtreleriyle seçim yapın. Yalnız eksikler seçeneği kurulu paketleri yeniden kurmaz. Güncelleme ayrı işlemdir; Arch tabanlı sistemlerde kısmi güncellemeden kaçının.

3. Diskler ve yedekler

lsblk -f
findmnt
id
sudo cp /etc/fstab /etc/fstab.bak

Diskleri ve UUID değerlerini kendi sisteminizden belirleyin. Başka cihazdan fstab kopyalamayın. Yedekleri ayrı bir aygıtta saklayın ve geri yüklemeyi deneyin. Disk biçimlendirme otomatik değildir.

4. SQL Server ve Docker

SQL Server Developer yalnız geliştirme ve test amaçlıdır. Portlar varsayılan olarak loopback adresine bağlanır. Docker erişimi yüksek yetki verir. Parola Docker ortamına kaydedilir; yetkili kullanıcılar görebilir. Veritabanı yedeklerini ayrıca alın. Portainer ve SQL imajları otomatik güncellenmez.

sudo docker ps -a
sudo docker volume ls

5. DBeaver ve Java

archlinux-java status
dbeaver -vm /usr/lib/jvm/java-21-openjdk/bin/java

Java 21 yolu mevcutsa ve DBeaver sürümü gerektiriyorsa özel yapılandırmayı seçin. Paket güncellemesi ayarı değiştirebilir. Java 8 gerekiyorsa yalnız güvenilir eski uygulamalar için ayrı kullanın.

6. Sanal makineler, VPN, Wine

Çekirdeğe uygun DKMS başlıklarını kontrol edin. Sanal diskleri dönüştürmeden önce kapatın ve yedekleyin. VPN profilleri, Windows uygulamaları, lisanslar ve kullanıcı hesapları bu dağıtımda yer almaz. Bunları kendi kaynaklarınızdan yapılandırın.

7. Kontrol

systemctl --failed
systemctl --user --failed
pacman -Qqe

Log dosyalarını paylaşmadan önce kullanıcı adı, dosya yolları, IP ve diğer özel bilgileri temizleyin.

Başlatma rehberi

15 · Güncelleme hataları ve güvenli dosya çakışması çözümü

Güncelleme aracını kapatın ve başka pacman/paru işleminin çalışmadığından emin olun. Çakışma mesajındaki dosya yolunu kontrol edin. Genel --overwrite veya otomatik yetim paket silme kullanmayın. Aşağıdaki adımlar yalnız belirtilen hata oluştuğunda uygulanır. Paket sahibi varsa durun. Yedekler benzersiz klasörlerde tutulur.

Flutter — .dart_tool dosya çakışması

Flutter ve IDE işlemlerini kapatın. Yalnızca aşağıdaki dosyaların paket sahibi olmadığını doğrulayın. Sahipli dosyayı taşımayın. Bu dosyalar proje kaynakları değil SDK tarafından üretilen dosyalardır; çözüm paket güncellemesinde doğrulandı, flutter doctor henüz doğrulanmadı.

1. Sahiplik kontrolü

pacman -Qo /opt/flutter/packages/flutter_tools/.dart_tool/{package_config.json,package_graph.json,version}

2. Yalnız sahipsiz dosyaları yedekle (kontrol otomatik tekrarlanır)

bash -c 'set -e
export LC_ALL=C
files=(/opt/flutter/packages/flutter_tools/.dart_tool/package_config.json /opt/flutter/packages/flutter_tools/.dart_tool/package_graph.json /opt/flutter/packages/flutter_tools/.dart_tool/version)
for f in "${files[@]}"; do
  if [[ ! -f "$f" || -L "$f" ]]; then echo "Beklenmeyen dosya: $f"; exit 1; fi
  if out=$(pacman -Qo -- "$f" 2>&1); then echo "$out"; exit 1; fi
  [[ "$out" == *"No package owns"* ]] || { echo "$out"; exit 1; }
done
b=$(sudo mktemp -d /var/backups/flutter-conflict.XXXXXXXX)
for f in "${files[@]}"; do sudo mv -- "$f" "$b/"; done
echo "Yedek: $b"'

3. Tam güncellemeyi yeniden dene

paru -Syu

4. Paket sürümünü doğrula

pacman -Q flutter-bin

RustDesk — masaüstü kısayolu çakışması

RustDesk oturumunu kapatın (uzaktan bağlıysanız bağlantı kesilebilir). Yalnızca paket sahibi olmayan kısayolu taşıyın; kullanıcı yapılandırmasına dokunmayın. Paket güncellemesi doğrulandı, bağlantı testi henüz yapılmadı.

1. Sahiplik kontrolü

pacman -Qo /usr/share/applications/rustdesk.desktop

2. Yalnız sahipsiz dosyaları yedekle (kontrol otomatik tekrarlanır)

bash -c 'set -e
export LC_ALL=C
files=(/usr/share/applications/rustdesk.desktop)
for f in "${files[@]}"; do
  if [[ ! -f "$f" || -L "$f" ]]; then echo "Beklenmeyen dosya: $f"; exit 1; fi
  if out=$(pacman -Qo -- "$f" 2>&1); then echo "$out"; exit 1; fi
  [[ "$out" == *"No package owns"* ]] || { echo "$out"; exit 1; }
done
b=$(sudo mktemp -d /var/backups/rustdesk-conflict.XXXXXXXX)
for f in "${files[@]}"; do sudo mv -- "$f" "$b/"; done
echo "Yedek: $b"'

3. Tam güncellemeyi yeniden dene

paru -Syu

4. Paket sürümünü doğrula

pacman -Q rustdesk

16 · Hyper-V / VirtualBox / VMware → KVM

Kaynak VM tamamen kapalı olmalı; checkpoint ve differencing disk zincirleri kaynak platformda birleştirilmelidir. Orijinali ve bir yedeğini koruyun. Uygulamada Sanal disk dönüştür düğmesi kaynak ve hedef seçimi, alan tahmini, sıkıştırma, ilerleme ve yapısal kontrol sunar. Hedef dosya varsa üzerine yazılmaz. Alan tahmini sıkıştırılmış çıktının kesin boyutu değildir.

sudo pacman -Syu --needed qemu-full virt-manager libvirt dnsmasq edk2-ovmf swtpm
qemu-img info "machine.vhdx"
qemu-img measure -f vhdx -O qcow2 "machine.vhdx"
df -h .
qemu-img convert -p -c -f vhdx -O qcow2 "machine.vhdx" "machine.qcow2"
qemu-img check "machine.qcow2"

Alternatifler (yeni, mevcut olmayan dosya adları kullanın):

qemu-img convert -p -f vdi -O qcow2 "machine.vdi" "machine.qcow2"
qemu-img convert -p -f vmdk -O qcow2 "machine.vmdk" "machine.qcow2"

Virt-Manager: mevcut disk imajını içe aktar; kaynak BIOS/UEFI tipini koru. İlk açılışta SATA ve e1000e tercih edilebilir. Kaynak disk ile hedefi eşzamanlı çalıştırmayın (IP/kimlik çakışabilir). Dönüşüm yapısal kontrolü Windows açılışını veya veri eşitliğini garanti etmez. VM kapaliyken istenirse qemu-img compare ile içerik karşılaştırılabilir. Hedef diskin büyümesi için boş alan bırakın.

Ethernet köprüsü — Hyper-V External Switch karşılığı

Uygulamada Ethernet köprüsü / br0 aracını açın. Aktif fiziksel Ethernet ve DHCP profili seçilir; mevcut br0 korunur. Statik IP profilleri otomatik işlenmez. Yerel konsoldan önizleyin ve onaylayın. İşlem sırasında bağlantı kesilebilir; DHCP alınamazsa geri alma denenir. Terminalde verilen geri alma komutlarını saklayın. Wi-Fi köprüleme otomatik değildir. Virt-Manager'da VM kapalıyken NIC: Köprü aygıtı, br0, e1000e; uygula ve başlat.

nmcli device status
ip -4 -br addr
bridge link

Fiziksel Ethernet ve vnet arayüzü master br0 / forwarding göstermelidir. Windows CMD: ipconfig /renew ve ipconfig /all. 169.254.x.x DHCP başarısızlığıdır. vnet arayüzü virbr0 üzerindeyse NIC ayarını düzeltin.

SPICE, QXL, RDP ve performans

Windows içinde SPICE Guest Tools kurup yeniden başlatın. SPICE kanalı ve QXL sürücüsüyle pano/çözünürlük işlevlerini deneyin. OpenGL kapalı kalsın. RDP için Remmina: istemci çözünürlüğü, 32 bit renk, dinamik çözünürlük; Windows uzak masaüstü etkin olmalı. Pano paylaşımı için RDP yönlendirmesini kontrol edin.

Get-CimInstance Win32_VideoController | Format-List Name,DriverVersion,CurrentRefreshRate

Öneri (otomatik uygulanmaz): host-passthrough, tek soket ve uygun çekirdek sayısı, ana sistemde yeterli bellek varsa RAM artırma. Windows VirtIO depolama ve ağ sürücüleri kurulup test edilmeden SATA/e1000e değiştirilmez. QXL raporlanan yenileme değeri fiziksel monitör hızını temsil etmeyebilir. Sıkıştırılmış QCOW2 ve NTFS üzerinde I/O performansı değişebilir.

Kaynaklar: QEMU qemu-img, NetworkManager örnekleri. Komut akışı gerçek bir geçişte doğrulandı; bu grafik araçların uçtan uca testi bekleniyor.
